# RefFlow 10.1.0：三阶段修复与验收

本次落实 [V10 逻辑审查](FULL-LOGIC-AUDIT-2026-10-15.md)中十个可复现问题，并实现长列表窗口化、跨客户端请求调度、按文库失效、可重建图形前端与导入取消。插件 ID、更新仓库及 Crossref / OpenAlex / Semantic Scholar 的来源角色保持一致。

## 第一阶段：身份与撤回

| 问题 | 实现 | 验收 |
|---|---|---|
| 同题不同作者/年份误配 | 新增 `workIdentity.ts`，本地匹配保留候选集并复用唯一身份核验；匹配缓存包含完整输入证据 | 不同作者/年份拒绝，正确身份仍可匹配，多个冲突 DOI 不选首条 |
| 批内仅标题去重 | DOI、arXiv、CNKI、S2 ID 和题名/作者/年份分层形成键 | 同题不同文献实际写入两个 Zotero 条目 |
| 旧批次删除后续复用对象 | v2 日志记录每条使用、关系、集合及创建时元数据；撤回扫描活动批次 | 同父/跨父复用、任意撤回顺序均不破坏仍被使用的数据 |
| 共享关系或集合被提前移除 | 将本批新增变化的清理责任转给仍需该变化的批次 | 最后一个使用批次撤回时才移除该变化 |
| 用户修改被连带删除 | 比较元数据、集合、关系和子内容；检查下载附件的批注及笔记修改 | 用户改题名、加集合/笔记、编辑清单、标注 PDF 或仅修改附件元数据后保留对象 |
| 旧日志缺少修改基线 | 保留无法证明可安全移除的旧条目，并显示保留数量 | 旧标记仍能清理批次记录，但不猜测条目属于可删除对象 |
| 损坏或未知活动日志 | 在任何破坏性操作前拒绝不完整的所有权协调 | 对象和原关系保持不变，返回错误 |

新增 `batchOwnership.ts` 分离日志类型、元数据快照和使用判断。元数据指纹排除宿主版本号、修改时间、程序管理的批次标记及关系/集合字段；关系、集合和子内容独立核验。保留共享对象后不强制将其“创建所有权”转移给其他批次，因此最后一个使用批次撤回后，某些保留条目仍可能留在文库中；这是保守的数据保护行为。

## 第二阶段：来源、完整性、缓存和字段映射

- Auto 与 API 共用 `onlineReferences()`，接通原有 CNKI URL / 中文标题分支；CNKI 故障可以继续 DOI 解析。Semantic Scholar 仍作为正式标题、DOI、references、citations 来源与回退。
- 手动 PDF、Auto、API fallback 统一计算编号缺口和部分结果，避免 `[1,3]` 被保存为完整表。
- Crossref 逐行隔离坏记录，保留原位置编号及损失标记，不再通过过滤坏行掩盖不完整性。
- 同签名有效旧快照优于较差的部分结果时，保留旧快照，不覆盖其保存时间；界面注明保留旧结果和本次取得数量。有效期结束后仍须重新评估，旧完整表不被永久视为当前事实。
- 持久保存开关按最终来源统一执行，包括 Auto / Web 和 PDF fallback。关闭保存禁止新增持久快照；已有快照仍按签名与有效期读取，不自动删除历史缓存。
- GB/T 的卷、期、页码贯穿解析、纯数据快照和 Zotero 字段映射；翻译器未提供的字段可使用已有解析值补齐。
- 缓存 schema 升到 4；在线策略签名为 `retrieval-v6`，PDF 为 `pdf-sdt-v3`，拒绝旧策略快照。

## 第三阶段：图形、性能和反馈

图形前端源码位于 `src/graph/`，由现有构建脚本生成安装包中的 HTML/CSS/JS。生产初始化没有示例论文。`RefFlowGraph` v1 接口负责 setGraph、setState、clear 与节点事件，宿主不再读写 Vue 路由、内部绘图对象或全局响应式变量。保留只读 `app.graphdata` 诊断别名，便于既有原生测试读取。

输入通过 `graphModel.ts` 校验，限制节点/边数量，拒绝无效文献和悬空边。使用服务返回的位置且保持比例；缺位置时使用确定性布局。界面提供来源、取得时间、相似性说明、空状态、深色主题、缩放、拖动和键盘节点操作。改变起始文献会清除旧图并取消旧任务。

超过 200 条参考文献时最多挂载 60 张卡片，以占位空间维持滚动范围。筛选、选择、复制和菜单仍基于完整数据；键盘能够跨窗口范围导航。较短列表保持原紧凑布局。本机 2,000 条样本首窗约几十毫秒，属于单机受控测量，不能外推为所有机器的延迟保证。

`requestScheduler.ts` 按服务与凭据在客户端之间共享 admission，保持订阅者取消、队列预算和槽位释放。原来的每客户端缓存、共享响应与冷却规则继续保留。导入器复用 Views 的工具/请求服务；文库通知只失效相关文库的匹配缓存和卡片，未知归属的事件保守全量失效。PDF 栏位候选改用位置桶，出版社嵌套节点去重改为祖先集合判断。

导入支持取消信号与默认五分钟操作预算，排队计入预算；侧栏取消按钮可停止导入。取消后不再开始新的条目/下载，元数据翻译器的迟到结果不会创建条目。每个完成的 OA 附件及时登记日志；已开始的原生附件下载等待完成和登记后再退出，不承诺在其传输中途立即硬中断。插件停用会取消导入并等待在途写入结束。

证据目录：`docs/evidence/repairs-2026-10-15/`。以下计数按分组报告列示，不把嵌套 wrapper 和子检查重复累加。

- 历史失败记录包括旧版本号、旧签名和“必须挂载全部 DOM”断言；更新为当前行为后重跑。未以简单丢弃失败来报告通过。

宿主为 Windows / Zotero 10.0.6 / Gecko 140，以及 Zotero 11.0-dev.5+dac1ad489 / Gecko 153。外部供应方使用受控响应；不据此承诺全部论文、账户、在线额度、其他 OS 或未来稳定版均已验收。

启动日志仍出现 `uncaught exception: undefined`。在关闭图形、参考文献 pane、设置、视图初始化、工具实例，直至测试包使用空 bootstrap、不加载任何 RefFlow 业务脚本的对照中仍可观察到。此证据说明不能简单归因于业务模块，但尚未确认宿主装载层的具体触发点；不声称启动日志完全干净。stream.zotero.org 的连接错误在无插件对照中也存在。

## 重现

```powershell
npm ci
npm test
$env:REFFLOW_NO_PROMOTE = '1'
npm run build
python scripts/verify-gecko153-package.py
pwsh -NoProfile -File scripts/run-isolated-native.ps1 -ScriptPath scripts/native-repairs-stage1.js -OutputPath tests/repairs-stage1.json -Wait -CloseWhenDone
pwsh -NoProfile -File scripts/run-isolated-native.ps1 -ScriptPath scripts/native-repairs-stage2.js -OutputPath tests/repairs-stage2.json -Wait -CloseWhenDone
pwsh -NoProfile -File scripts/run-isolated-native.ps1 -ScriptPath scripts/native-repairs-stage3.js -OutputPath tests/repairs-stage3.json -Wait -CloseWhenDone
```

综合 HTTP 回归另需启动 `python scripts/native-http-server.py`。测试开发宿主时传入独立 `-ZoteroPath`。所有写入必须使用运行器创建的独立配置与文库，不能替换为日常主文库。
