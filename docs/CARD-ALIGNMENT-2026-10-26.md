# Zotero RefFlow 图标、箭头与标题对齐优化

日期：2026-10-26。针对用户截图中状态点与箭头难以对应标题的问题，在维护仓库 `groele/Zotero-RefFlow` 的 `main` 上调整卡片布局。保留前一轮未提交修改，版本继续使用未发布候选 `12.5.4`；未安装到主 profile、提交新 Git 历史或发布 Release。

## 调整后的布局

- 第一行区域保留来源编号及引用原文，原文使用除编号外的完整宽度。
- 独立标题行将状态圆点、加粗题名及操作按钮放在同一网格；圆点和箭头对齐标题首行中心，长题名换行不改变图标位置。
- 作者、年份、期刊与题名的文字左边缘一致。多位编号使用同一宽度的编号栏；撤稿提示保持显示。
- 添加、在库定位、处理中及失败四种状态共用稳定的 SVG 画布和按钮尺寸，保留原有本地化标签。SVG 仅作装饰，按钮的可访问名称继续描述实际操作。
- 操作按钮至少 24×24 CSS px，随字号增长，带独立悬停及键盘焦点样式。双击按钮不再冒泡触发整张卡片的双击跳转；双击卡片仍保留原行为。
- 字体放大时，虚拟列表行高、上下占位及滚动计算使用相同的实际行高；元信息在虚拟模式最多显示两行，完整文本通过悬停提示保留。普通短列表自然排版，不设置固定高度。
- 新卡片样式限定到带 `data-refflow-item-id` 的 RefFlow 面板，即使宿主其他相关条目区域出现相同通用类名，也不受这些样式影响。

没有修改 DOI 导入、目标分类、身份核验、批次所有权、撤回规则或供应方顺序；上一轮的 PDF 下载结果及空日志保护继续保留。

## 复现与中间问题

旧包上的新增布局检查未通过，截图及几何结果保留为基线。初版布局检查另发现：固定 144px 虚拟行高在 135% 字体下会裁切长题名/元信息；本轮已改为随字号计算行高。

已有滚动测试仍假定每行 144px，改为从真实卡片高度计算“滚动 1000 行”，保留原来的后段编号与 60 条挂载上限断言。图标断言随 SVG 更新为操作状态，继续核验本地匹配、失败重试与成功定位，而不依赖字体字符。

首次状态位置检查比较了全窗 Y 坐标，受上方宿主区域展开影响；最终比较按钮相对卡片的位置，同时核验相对标题的中心差。另一次回归因 Windows 报告文件的读取锁阻止宿主原子替换，测试 runner 已使用允许删除/重命名的共享读取流。最初 TypeScript 空值提示、失败报告和中间包均保留；没有通过删除断言消除失败。
