# 数据流与接口规范

本规范按用户于 2026-10-12 的明确要求制定。Semantic Scholar 是正式数据源；架构升级不得将其删掉或静默禁用。

## Semantic Scholar 必须保留的能力

使用官方 Academic Graph API：`https://api.semanticscholar.org/graph/v1/`。按本轮核对的[官方接口规范](https://api.semanticscholar.org/api-docs/)执行；外部接口变化时重新验证。

| 能力 | 官方接口 | 数据流规则 |
|---|---|---|
| DOI 元数据 / paperId 解析 | `GET /paper/DOI:{encodedDOI}` | DOI 先归一化，再编码路径；校验返回 `externalIds.DOI`；请求所需字段，保留返回的 paperId |
| 标题检索 | `GET /paper/search` 或 `/paper/search/match` | 检查标题、作者、年份和 DOI 一致性；不得仅凭第一条结果决定身份 |
| 参考文献 | `GET /paper/{paper_id}/references` | 使用 `citedPaper`；方向是原文引用的文献；跟踪分页和无法解析的记录 |
| 被引文献 | `GET /paper/{paper_id}/citations` | 使用 `citingPaper`；方向是引用原文的文献；与 References 数据隔离 |

保留 Semantic Scholar 的独立兜底角色：Crossref/OpenAlex 缺少原文记录或参考文献时，仍尝试其官方接口。其他来源不完整时可以比较独立候选列表，但不得拼接不同来源的编号并宣称是原文顺序。

## 网络、缓存与结果约束

1. HTTP 必须经过应用请求服务；取消信号覆盖查询、分页、补全和退避等待。一个消费者取消不能破坏其他消费者的共享请求。
2. 若配置 API Key，按官方要求使用 `x-api-key` 头。日志和审查证据不得包含凭据。
3. 遵守 HTTP 429、Retry-After 和总请求预算。限流/网络失败、合法空结果及用户取消必须能区分，不得把短暂失败长期缓存成“无文献”。
4. 有 next offset/cursor、达到数量/时间预算、缺失 citedPaper/citingPaper 或元数据解析损失时，结果标为 partial/truncated；不得把首个 100 条页面当作完整文献表。
5. 每条文献保留来源；本地匹配只能增加运行时关联和状态，不得修改已持久化的供应方证据。
6. 缓存必须隔离文库、条目、文献类型、来源/提取模式和全文/局部范围；验证签名和有效期，存储纯数据副本。
7. 本地检索、渲染与导入必须使用操作所属条目/窗口/文库，不依赖稍后变化的全局选中对象。
8. 图谱列表的位置序号不得宣称为原文引用编号；供应方撤稿证据不得被本地复查覆盖。Crossref/OpenAlex/Semantic Scholar 的父 DOI 身份必须验证。
9. 预算覆盖完整供应方操作，包括父查询、队列、补全和分页；整条刷新另外受协调器截止时间限制。预算耗尽不得继续生产新请求，且已有部分结果须保留完整性标记。
10. 缓存同时受数量、单项和总 UTF-8 字节预算约束；返回拥有的数据副本。认证 POST 不缓存，未提供文库的持久缓存操作不得猜测个人库。
11. 本地新增默认通过规范化 DOI 调用 Zotero 原生 Search 翻译器；返回须具有相同 DOI 和非空标题。超时、网络异常、无结果、缺 DOI 或身份冲突均作为可重试失败，禁止静默回退为供应方简略条目。无 DOI 时先匹配已有本地文献；未命中则明确跳过。仅调用方显式传入 `allowMetadataWithoutDOI: true` 时，才允许对无 DOI 文献使用已有元数据创建；此选项不能绕过有 DOI 时的原生身份核验。文献导入只创建常规文献类型。
12. 任务身份包括正在使用的附件和检索字段快照。同一父条目不代表同一 PDF；元数据在请求途中改变时，不得提交编辑前的响应。
13. Crossref、OpenAlex 与 Semantic Scholar 的标题查询共用身份选择规则：先核验候选，再检查唯一身份；结果排序不能作为身份证据。只有一个通过核验的 DOI/来源 ID 才能自动采纳，已有作者/年份需获得对应佐证。统一 DOI 解析器按来源回退，单个来源故障不能跳过后续 Semantic Scholar。
14. 列表完整性在选择前统一计算，并贯穿缓存与界面。status=partial、数量缺口、混合/跳号编号及坏记录损失都不能被改为 success。逐条隔离坏记录；部分查询没有可用记录时按 unavailable 处理，不能当成确认空文献表。
15. OpenAlex 分页按验证后去重的有效记录计数，不能因重复行达到原始行数就提前结束。缺失 related_works 不代表确认没有相关文献。缓存签名包含检索策略版本；新身份核验规则不能继续读取旧策略的结果。

## Zotero 集成约束

逐项对照[Zotero 10 开发说明](https://www.zotero.org/support/dev/zotero_10_for_developers)和实际安装源码；使用原生 ItemPaneManager、数据对象、事务和受支持的 Reader/结构化文本服务。不得调用已移除的单选集合 getter、CookieSandbox、fulltextWord 等旧接口。

区分“被移除的旧接口”和“当前可用但属于内部实现的接口”。若尚未找到可保持功能质量的公开替代，明确记录边界，不能把内部调用称为公开稳定接口。

## 必要验收

- Crossref 与 OpenAlex 都缺失时，Semantic Scholar 官方接口仍能提供候选。
- DOI 元数据、标题检索、references、citations 均保留；引用方向正确。
- 标题相同而 DOI 不同不得合并。
- 分页、缺失记录、限流、取消、迟到响应及缓存失效均有测试。
- 测试只读取或写入隔离配置和文库；受控供应方响应与真实在线验证分别标注。


## 10.1.0 本地数据与交互契约

- 本地文献身份以规范 DOI / arXiv / CNKI / S2 ID 及题名、作者、年份证据区分；题名匹配复用统一候选核验，歧义时不挑第一条。
- 批次日志 v2 记录创建基线及每条使用。撤回在单文库队列中协调活动日志，只清理本批新增且不再共享的关系/集合；用户修改、子笔记、附件批注或附件元数据变化保护对应父项。旧日志无修改基线时保留条目；损坏活动日志拒绝破坏性协调。
- 参考文献快照 schema 4；在线签名 `retrieval-v6`、PDF 签名 `pdf-sdt-v3`。较差的部分结果不得覆盖有效的更完整旧快照，旧时间戳不刷新。持久保存开关按最终来源执行。
- 图形数据先校验节点、边和数量，再由 `RefFlowGraph` v1 的 `setGraph` / `setState` / `clear` 驱动独立 SVG 前端；事件通过带版本的 `refflow-graph-event` 传递。相似性关系不能标作引用方向。
- 超过 200 条的列表最多挂载 60 张卡片；筛选、选择、复制和键盘导航基于完整数据。缓存通知按文库失效，无法归属的通知保守全量失效。
- HTTP admission 按服务及凭据跨客户端共享，取消和预算覆盖排队时间。导入默认五分钟预算；取消不启动新写入，已开始的原生附件下载需完成登记后退出。

实现及受控原生验收边界见 [10.1.0 修复报告](REPAIRS-2026-10-15.md)。


## 2026-10-21 DOI 本地导入交互约束

- 单项与批量、侧栏与图谱复用同一 DOI 导入链。翻译器仅获取元数据（`libraryID: false`、`saveAttachments: false`），创建与关系写入仍由现有事务及批次所有权日志管理。
- 操作开始即快照引用信息及目标分类；重复 DOI 共用当前批次内的解析结果，重复界面请求共用同一个进行中的任务。
- 全部缺 DOI 或解析失败时不创建空分类、清单笔记或批次日志。失败明细保留位置、DOI、标题和原因。
- 单项按钮显示忙碌状态；失败、取消后恢复可重试。已存在文献直接定位。批量完成仅刷新本地匹配，避免重跑在线文献检索。
- 验收覆盖 DOI URL/大小写归一化、重复条目、缺 DOI、缺返回 DOI、冲突 DOI、空标题、空结果、超时迟到、取消、只读库、目标分类变化及失败重试。原生在线与受控原生测试分别记录。

## 2026-10-25 导入一致性补充

- DOI 解析保留配对括号与旧式 SICI 后缀，处理复制时的全角/不可见字符、百分号编码和 DOI URL 的跟踪参数；单个 DOI 字段含多个标识符时拒绝猜测。
- 翻译器结果按请求 DOI 核验候选，不依据返回顺序选取第一条。界面提示使用本地化错误类别，诊断结果仍保留原始原因。
- 新建前在同一个写事务中进行不依赖显示缓存的查重；等待期间由原生标识符框、其他插件或同步新增的文献应被复用。
- 分类、条目、关系和首条批次日志在同一事务提交；首次写入失败不留下空分类或日志。失败恢复不得掩盖最初的异常或抹去先前成功记录的使用权。
- 导入写入传入 `skipSelect: true`，避免 Zotero 自动选择新条目并切换操作所属面板。成功重试必须同时更新按钮与状态栏，不能保留上次失败说明。
- 分类来自操作所属窗口，限定在父条目的文库；检索前及提交前校验分类是否仍存在。面板切换后，旧按钮不得启动新导入、定位条目或覆盖新面板状态。
- 图谱的数字年份与字符串年份使用统一身份核验；图谱导入操作可通过键盘聚焦，进行中禁止重复触发。
- 带独立取消信号的调用不共享任务所有权；无独立信号的相同请求仍合并。翻译器超时及总预算参与任务身份；已排队取消也返回明确的取消结果。

实现、验证范围及复现命令见 [本轮优化报告](OPTIMIZATION-2026-10-25.md)。

## 2026-10-26 撤回与窗口归属补充

- 现代批次记录的保护证据在写事务获得执行权后读取；排队期间的用户编辑必须参与保留判断。撤回失败后重新加载已接触的数据对象，批次日志保留为可重试状态。
- 创建条目的分类或关系既包括新增，也包括从创建基线中移除的变化；用户组织或编辑过的内容不得因撤回被送入回收站。
- 新建分类记录 key、名称与父级的创建基线。仅清理身份与结构未变、没有活动条目或任何子分类、且无受保护创建条目的本批空分类。旧日志无分类基线时保守保留分类，不补造历史基线。
- 主日志与其他活动日志逐层校验 ID、数组、使用权、附件及基线结构；无法核实的日志阻止破坏性协调。旧标记清理只匹配插件的完整行，保留当前 Extra 中的用户内容与迟到编辑。
- 本地匹配的显式 DOI 优先约束所有候选；相同 arXiv/CNKI 不能覆盖冲突 DOI。
- 卡片、批量和图谱导入携带仅限运行时的 owner；取消和窗口关闭只停止所属任务。不同 owner 的相同 DOI 请求不共享取消所有权，同 owner 的重复请求仍可合并。无 owner 的程序调用保留显式按父条目或全局取消的接口。
- 撤回仅刷新本地匹配，保留当前检索列表、来源和筛选；成功与失败通过本地化状态提示表达，不以在线重新检索代替撤回结果。

具体复现与验证边界见 [继续审查报告](REVIEW-2026-10-26.md)。

## 2026-10-26 解析生命周期与列表视口补充

- DOI 解析在超时、取消或完成后退役本次活动状态；迟到的翻译器发现结果不得启动下一解析阶段，迟到元数据不得进入写入链。已经启动的宿主传输是否能强制中止须单独验证，不能以等待超时代替网络取消证明。
- 清理文献列表时重置虚拟视口与当前列表回调；列表变短时保留最后完整的有界窗口，滚动计算使用同一上界。筛选集合的无障碍位置与数量对应当前结果，原始文献编号独立保留。
- 卡片、菜单和图谱统一按导入错误类别生成本地化提示；目标库、起始条目等前置失败使用现有 destination 类别，原始诊断保留。
