# Zotero RefFlow 16.2.0

- Store each paper in a separate readable JSON file under `<Zotero data directory>/refflow-reference-cache/<libraryID>/<itemKey>.json`, with a lightweight `index.json` for capacity, access times and retention metadata.
- Load paper payloads on demand and write only changed paper files plus the index. Serialize operations, use atomic file replacement, and rebuild missing or interrupted index entries from paper files.
- Start a fresh cache as requested. Previous collective cache files are excluded from the new store.
- Add paper-file capacity settings of 1–64 MiB and 10–10000 papers, defaulting to 8 MiB and 250 papers. The per-paper limit is 2 MiB. Index usage is reported separately.
- Show cache folder, current usage and session eviction, expiry and oversized-save counters in preferences.
- Remove expired lists at startup, after retention changes, every ten minutes and through a manual cleanup button. Complete lists default to 30 days. Zero-day retention remains unlimited subject to capacity eviction.
- Preserve independent PDF, reference and neighborhood policies, library isolation and scoped API refresh behavior.

Shared reference metadata deduplication remains future work.
