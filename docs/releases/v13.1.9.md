# Zotero RefFlow 13.1.9

Released 2026-11-03. Emergency regression fix for main library item detection and sidebar rendering, complete restoration of native Reader resolution, and stabilization of the 5+1 modular preferences layout.

## Highlights & Fixes

1. **Critical Fix: Main Library Item Selection & Reference List Rendering**:
   - **Root Cause Identified**: In versions 13.1.7 and 13.1.8, an over-engineered multi-tier `getReader(win)` implementation traversed `Zotero.Reader._readers` matching `topWindow === win`. In the main Zotero library pane, background PDF tabs share the main window as their `topWindow`, causing `getReader(win)` to mistakenly return background reader instances instead of `undefined`. Consequently, `getItem(win)` returned background attachments instead of the currently selected library item, triggering a `sameInput()` mismatch and preventing reference cards from rendering (resulting in an empty sidebar).
   - **Fix Applied**: Completely restored the clean, proven native implementation of `getReader(win)` and `getItem(win)` from the stable v13.1.6 baseline. When viewing the main library, `getReader` strictly yields `undefined`, allowing `getItem` to directly and reliably query the active selection from `ZoteroPane.getSelectedItems()`.
   - **DOM Method Restoration**: Reverted synthetic namespace wrappers back to native `doc.createXULElement(...)` across `views.ts`, `referenceCards.ts`, and `connectedpapers.ts`, preserving native Gecko XUL popup prototypes and menu behaviors.

2. **Modular 5+1 Preferences Maintained**:
   - Kept the verified 5+1 business-driven settings panel layout (`preferences.xhtml`): Literature Retrieval & Sources, Reference List & Card Display, Hover Tooltips, Batch Import & OA Fulltext Downloads, Online Academic API Keys, and About RefFlow.
   - Maintained full 3-language parity (`zh-CN`, `en-US`, `it-IT`) with zero missing keys.

3. **Regression Test Suite**:
   - Verified 344 unit tests passing cleanly with zero regressions.
