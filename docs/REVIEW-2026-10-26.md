## 已复现并修复

| 问题 | 用户影响 | 修复 |
| --- | --- | --- |
| 移除原分类/关系未被视为用户编辑 | 撤回可能删除已由用户重新组织的文献 | 对照完整创建基线，同时保护增加与移除的变化 |
| 撤回决策早于事务实际执行 | 事务排队期间的用户编辑可能被旧删除计划忽略 | 将日志读取、共享权利协调和保护判断放入写事务 |
| 空批次分类没有创建基线 | 用户重命名、移动后的空分类可能被删除 | 新记录保存分类 key/名称/父级；有变化或无法验证历史基线时保留 |
| `hasChildItems()` 包含回收站条目 | 未编辑的批次空分类无法随撤回清理 | 依据实际宿主 API 区分活动条目与回收站；保留有子分类或受保护内容的容器 |
| 日志只校验顶层字段 | 内层损坏的使用权或基线不能可靠参与协调 | 在任何破坏性协调前逐层校验，损坏时拒绝撤回 |
| 撤回事务失败后对象缓存可能保留中间状态 | 界面关系与真实数据库不一致，重试不可靠 | 追踪接触的对象，失败后重新加载并保留原始错误与日志 |
| 旧标记按行后缀清理、使用旧 Extra 快照 | 同后缀用户笔记或等待期间的编辑可能丢失 | 仅删除完整插件标记行，使用操作结束时的当前 Extra |
| arXiv/CNKI 命中早于 DOI 冲突过滤 | 引用可能错误复用不同 DOI 的本地条目 | 显式 DOI 约束应用于所有二级标识符候选 |
| 取消按父条目全局作用 | 一个窗口取消会影响另一窗口的独立导入 | 按运行时 owner 限定取消和任务合并；窗口关闭撤销所属等待 |
| 撤回后重新检索、技术错误直接显示 | 增加网络请求，用户难以判断本地操作结果 | 只刷新本地匹配，增加中英意成功/失败提示 |

日志仍为兼容的 v1/v2 格式，新增 `collectionState` 为可选字段。旧记录不会被伪造新基线，缺乏充分证据时优先保留数据。owner 不持久化，不改变插件 ID、偏好命名空间或历史数据目录。
