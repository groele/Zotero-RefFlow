# RefFlow 日志加固：实现与验收（2026-10-27）

## 已完成

本轮按实现方案逐步执行，先保存已有候选改动，再加固日志和恢复界面。基线副本位于任务目录 baseline/，未清理其他任务材料。期间共享仓库完成另一项 12.5.6 发布提交；本轮后续构建与测试改在独立 validation-source/，避免共享 build/ 相互覆盖。评估包不等同于已发布 12.5.6 的资产。

1. **条目身份覆盖**：统一枚举父项、新建项、关系端点、附件与其父项、成员项、uses、states 和笔记。现存对象缺少稳定 key、key 改变或文库不匹配，拒绝读取和破坏性撤回；已删除对象不被猜测为新身份。更新旧日志保持顺序。
2. **提交后故障恢复**：在事务前保留 previous 快照。数据库提交后最后写入失败返回明确的 JournalCommitPendingError，停止把该项归入普通元数据失败并避免重置已提交的记录。保留本进程确知提交的草稿；下一操作或“完成日志保存”按钮可仅重试文件终结，不重新运行数据库业务。恢复还要核对 pending 文件与确知提交的草稿完全一致，外部变更则拒绝覆盖。
3. **未知 pending 保护**：重启后无本进程提交证据时不自动改标记、不删除文件、不推测回滚；显示检查/备份指引并可复制只包含状态和备份可用性的脱敏诊断。这里保留人工核验边界，不宣称实现了跨进程自动事务恢复。
4. **多库隔离**：导入和撤回显式携带文库 scope；另一明确归属文库的坏记录原样保留，不阻塞正常文库。文件头或无法归属的损坏仍保守拒绝。单事务不得读写不同 scope。全局 unknown pending 仍阻止写入，因为它可能包含多个文库的未决事务。
5. **减少无效工作**：以 dirty 标志取代全文件 stringify 比较；只读事务和完全相同条目更新不写日志。双阶段原子写入及 previous 备份保留；全量文件读写带来的大规模成本尚未通过迁移架构消除。
6. **迁移与撤回反馈**：迁移成功后才记录父项，失败后同窗可再次尝试。提供检查日志状态入口及安全恢复按钮。撤回结果逐调用返回 removed/retainedIDs，UI 不再依赖共享 lastRollback；旧数字返回接口与静态镜像保留兼容。
7. **重试会话历史**：第二次及之后显示各次尝试的独立结果，区分首轮与重试；撤回后清除旧结果与旧重试控件。不会把多次尝试误合成一个可批量删除的操作，也不自动扩大撤回范围。
8. **附件收尾**：日志终结错误不标成 PDF 下载失败；等待已启动 worker 收尾，停止生产后续下载任务后才退出，避免后台写入逃出批次队列。

界面新增中文、英文、意大利文文案；诊断不复制私有标题、完整路径、API Key 或认证头。

关键原生故障注入是在真实 DB 提交后创建日志 .tmp 同名目录，使最后一次原子写入失败；观察到条目已保存、日志 pending，随后通过恢复按钮完成日志保存，再导入同 DOI 得到 existingCount=1、importedCount=0。未知 pending 的界面不提供恢复按钮，也不修改文件。实际重启后保留 Extra 和日志，撤回按记录只删除有归属的项目。

回归首次出现两项“失败行数”断言失败，因为历史列表新增 li；将选择器限定到失败列表，并加入历史条数和撤回清理断言，原断言没有删除。最终 17 项通过。另一次报告原子替换受 Windows 临时锁影响，新增仅限本次报告路径的 4 次有界重试；原始故障 IO 不做重试。用真实临时文件锁单独验证 1 项通过，不计入产品 180 项。

## 保留边界

- 未发布新版本、未移动标签、未安装用户主 profile。本轮没有覆盖正式安装包和更新源；同一工作区其他任务的发布结果独立于本轮评估包。
- 跨设备同步/配对恢复、旧版降级及未知 pending 的自动恢复仍不成立；需要保留日志与同一库备份。
- 大规模真实磁盘 p50/p95、10000 项日志归档和数据库侧持久提交凭证仍是后续工程项。本轮减少了无效写入，没有宣称解决全部写放大。
- 日志 scope 只隔离可明确归属的记录损坏，未知文件损坏仍全局停止，安全优先于猜测。
- Zotero 11、其他系统、屏幕阅读器实读和自动更新端到端未新增验收。

## 复现

先用 REFFLOW_NO_PROMOTE=1 运行 npm test 与 npm run build。原生日志入口为 scripts/native-batch-journal.js；重启同一 profile 后自动进入重启验收并写 -restart.json。脚本只允许 refflow-z10-release-* 独立库。依赖固定端口的 DOI 与附件套件串行运行，普通 UI 套件可使用独立 profile。
