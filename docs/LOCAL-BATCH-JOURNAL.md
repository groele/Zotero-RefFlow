# 本地批次记录

RefFlow 将导入批次的所有权、关系、集合和元数据基线写入 Zotero 数据目录中的 `refflow-batch-journal-v1.json`，不再把内部 `refnexus_batch_parent`、`refnexus_record_*` 和 `import_batch` 标记写入条目的 Extra（其他）字段。文件是持久的撤销日志，不受普通响应缓存清理或过期淘汰影响。

- 新批次保留原始 Extra。JCR、影响因子、SCI、ESI 和手写文字属于用户字段，不在本次迁移中删除。
- 打开含旧记录的 RefFlow 参考文献侧栏，或执行导入／撤销时，验证同库旧日志，将它们存入 JSON 后只清理对应内部行。迁移在同一数据库事务中执行；本地文件准备写入失败时回滚并恢复内存条目。
- 按文库、父条目 ID、父条目 key 和批次 ID 隔离记录，并保存关联条目的稳定 key，避免数字 ID 复用被当作原批次证据。
- 共享条目、手工编辑、附件批注、笔记、集合变化和用户增加的关系继续受到原有撤销保护。撤销上次导入从 JSON 获取批次，旧批次的所有权更新不会改变导入顺序。
- 全局文件写队列协调不同文库，原生事务内写入 `pending: true` 的临时提交；数据库提交成功后标记为完成。数据库提交失败时恢复之前文件。损坏、未来版本、未完成事务均保留原文件并阻止进一步导入／破坏性撤销，不自动重置日志。
- 本进程确知数据库已提交而文件终结失败时，可通过“检查本地批次记录”中的按钮完成日志保存，不重复导入；恢复会核对文件未被改动。保留上一份 `.previous` 快照。重启后无法确认来源的 `pending: true` 继续阻止写入，应保留日志和同一库备份并核验；不能删除文件或直接改标记猜测结果。错误不代表已提交数据已撤回。
- 旧版本降级不能读取新本地日志。此文件不通过 Zotero 同步；迁移后跨设备的批次撤销需要对应本地文件与同一库数据，不能仅凭同步的条目猜测批次所有权。
- 旧日志损坏或仅有无基线的早期标记时不猜测所有权，不批量删除原文或条目。

12.5.7 正式发布使用通过隔离验收的同一生产包，更新源指向固定版本 Release 资产。安装后打开含旧记录的 RefFlow 参考文献侧栏可触发迁移。发布操作不自动安装到用户主 profile 或修改主库。
