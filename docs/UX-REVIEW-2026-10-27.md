# RefFlow 深度检验与体验优化（2026-10-27）

## 结论与范围

从已发布的 12.5.5（1575c05）开始检查。仓库为 groele/Zotero-RefFlow，main 开始时干净并与 origin/main 同步。重点审查文献卡片、DOI 导入与错误反馈、批次撤回、网络/缓存状态及原生测试链路。

本轮实现两项体验改进，并修复旧原生测试与现行契约脱节的问题。正式 12.5.5 XPI、update.json 和已发布标签未变。本轮构建为本地评估包，未安装用户主 profile，不代表新增 Release。

## 已复现并修复

### 1. 长列表键盘操作不完整

发布包上的真实 Zotero 基线测试：11 项中 6 项失败。End、PageDown、Space、Shift+End、筛选后 End 及普通列表 End 场景无法完成预期操作。原有 Home/PageUp 等个别基线通过只是当时焦点已在起点，不作为已有完整支持的证据。

修复后支持：

- Home / End 跳到当前筛选结果的首尾。
- PageUp / PageDown 按可见视口翻页，普通列表按实际卡片高度估算，不依赖固定字体。
- Space 选择，Ctrl/Command+Space 切换选择，Shift 范围选择跨越虚拟窗口仍保留锚点。
- 跳转后滚动到焦点附近；500 项与筛选后的 250 项可跨窗口跳转，挂载数量仍不超过 60。
- 聚焦卡片操作按钮时，列表不拦截按钮的键盘事件。

新增原生测试验证以上路径以及原有上下方向键；不宣称已经完成 Narrator/NVDA 语音验收。

### 2. 快速悬停时旧计时器关闭新提示

基线实际卡片 DOM 事件 + 受控提示对象复现：A 卡片离开后预约关闭，B 卡片提示已显示，A 的回调通过 this.tip 关闭 B。旧对象还可能保留计时器。

修复：统一 clearTip，先取消所属计时器再清理提示；替换提示前退休旧对象；离开事件捕获具体提示身份，只在仍属于当前提示时关闭。列表清空同样取消相关计时器。

新增测试验证旧计时器不会清理新提示且旧提示被清理。该计时器归属场景使用受控提示对象；旧汇总套件另外覆盖真实 TipUI 元数据悬停及无额外 enrichment 请求。

### 3. 原生测试工程链路脱节

扩展执行旧 native-final 入口时出现失败，保留原始报告 core-final* 和 legacy-final*，未删除断言掩盖失败。

- 两个纯元数据数据库/附件 fixture 无 DOI，却默认要求新增成功。现在显式使用已有 allowMetadataWithoutDOI 测试入口；默认产品交互仍拒绝无 DOI 新建。
- 超时测试仍要求迟到翻译器创建一条文献。改为要求两次明确 timeout 失败、零新增条目、不同独立任务 batch ID、回滚安全；以独立 AbortSignal 区分任务，避免把正常的相同请求合并误判为 batch ID 冲突。
- 旧单卡片测试要求无 DOI 创建成功。改用已经在本地的规范 DOI，验证卡片操作复用该本地项；新增关系和真实在线 DOI 创建由当前 DOI 工作流另行覆盖。
- 公开 PDF fixture 缺失导致 NS_ERROR_FILE_NOT_FOUND。增加 prepare-online-fixture.py：按固定公开来源下载，核验 PDF 头与 SHA-256，已有不同文件拒绝覆盖；native-online 缺文件时给出明确准备命令。

公开 PDF 来源 https://arxiv.org/pdf/1706.03762，2215244 字节，SHA-256 bdfaa68d8984f0dc02beaca527b76f207d99b666d31d1da728ee0728182df697。下载文件属于被忽略的测试材料，不提交二进制论文。

## 下一阶段建议：按用户收益与风险排序

| 优先级 | 当前依据 | 建议及验收条件 |
|---|---|---|
| 高 | referenceCards 菜单批次摘要仅取 failures[0] | 批次结果抽屉显示每项 DOI、位置、阶段、原因；可复制失败 DOI、仅重试失败项。保留批次原始父项/目标集合，成功项不重复，集合被删除时明确停止。 |
| 高 | metadata 保存与 PDF 下载是两个不同阶段，已有独立计数 | 显示解析、保存、下载、收尾状态；取消后告知已开始的原生下载可能仍在收尾。必须准确登记已完成附件，不能宣称底层传输已强行终止。 |
| 高 | 来源、partial、expected、latestAttempt 与 attempts 已存在，但主要分散在摘要/tooltip | 提供“结果来源与完整性”详情，显示来源选择、已有/预期数量、缓存时间、保留旧结果原因、失败来源。部分结果绝不标为完整，不混合独立供应方顺序。 |
| 中 | views.rollbackReferences 在 await 后读取静态 lastRollback | 改为每次调用返回自己的 removed/retained/reasons，并保留旧数字接口兼容；两个不同文库交错撤回时摘要必须各自正确。这是代码层面的并发呈现风险，尚未复现数据丢失。 |
| 中 | Requests 已暴露 metrics 和 cacheUsage，存储已有隔离与限额 | 提供默认脱敏诊断：请求、重试、超时、取消、缓存命中、队列、持久化失败。禁止包含 API Key、认证头、私人标题和完整路径。 |
| 中 | 超过 200 项虚拟化，已验证 2000 项最多挂载 60 张卡片 | 加 500/2000/10000 项的首次显示、筛选、滚动、批次日志序列化基准。记录 p50/p95、内存及 Extra 字节数，再决定是否改变日志存储；不能凭感觉重构。 |
| 中 | 只有 Windows Zotero 10.0.6 真实运行证据 | 扩展 Zotero 11、真实只读群组、权限中途变化、离线/机构代理、Narrator/NVDA。兼容声明 10.0.6–11.* 不等于 Zotero 11 已验收。 |

建议下一轮优先实现“批次结果明细 + 失败项定向重试”，把已有结构化失败信息转为可操作的恢复入口；再完善下载过程和来源完整性说明。上述是待实施项目，不作为本轮完成项。
